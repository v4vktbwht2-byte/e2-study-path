# 14. Accessibility, Privacy, and Security

## 1. Accessibility target

WCAG 2.2 AAを目標とする。完全適合を宣言する前に手動検証が必要。

## 2. Keyboard and focus

- すべての主要操作をキーボードで完了可能
- 論理的なフォーカス順
- フォーカストラップはDialog内だけ
- Dialogを閉じたら起点へ戻す
- ルート遷移時に見出しへフォーカスまたは適切なアナウンス
- ショートカットは入力欄と衝突させない

## 3. Screen reader

- 画面に1つの主見出し
- ナビゲーションランドマーク
- 進捗は値とテキストで通知
- 正誤フィードバックはlive regionを適切に使う
- 音声再生ボタンに状態を付ける
- グラフは要約テキストを持つ

## 4. Visual

- 文字倍率200%でも主要操作が欠落しない
- 320px幅で横スクロールを原則発生させない
- 色だけで正誤や状態を示さない
- フォーカスリングを消さない
- タッチ領域44px以上
- `prefers-contrast` 等は可能な範囲で配慮

## 5. Cognitive accessibility

- 1画面1主要行動
- 専門用語に説明
- 長い説明は見出し・例・要点へ分割
- タイマーは練習モードでは停止可能
- 診断や試験モード以外で不要な時間圧をかけない
- 誤答時に修正方法を示す

## 6. Motion and sound

- `prefers-reduced-motion`
- アプリ内の動き軽減設定
- 自動音声再生は設定可能
- 音声だけで情報を伝えない
- 録音開始・停止を視覚的にも示す

## 7. Privacy

コアリリース:

- アカウントなし
- 外部分析なし
- 広告なし
- 学習履歴は端末内
- マイクはスピーキング練習で明示操作した場合のみ
- 録音は端末内
- ユーザーが削除可能

プライバシー説明画面には、保存場所、バックアップ方法、削除方法、録音の扱いを書く。

## 8. Permissions

### Microphone

- 必要になるまで要求しない
- 要求前に目的を説明
- 拒否時に再要求を繰り返さない
- テキスト練習へフォールバック

### Notifications

Pilotでは必須にしない。将来追加時も明示操作後に要求する。

## 9. Security

- ユーザー入力とコンテンツをraw HTMLとして描画しない
- import JSONをschema validation
- ファイルサイズ上限
- zip爆弾等の複雑importはPilotで扱わない
- URLは許可schemeのみ
- 外部リンクは明示
- `target="_blank"` 時は安全なrel
- Content Security Policyを静的ホストで可能な範囲で設定
- 依存関係監査をCIまたはリリース時に実行

## 10. Backup safety

- schema version確認
- import前に要約表示
- 置換とマージを区別
- 置換前に自動安全バックアップを生成可能にする
- 不正データは一部だけ黙って取り込まない
- エラー箇所を示し、元データを維持

## 11. Data deletion

- 二段階確認
- 入力確認または明確な長押し等を使ってもよい
- 削除対象を列挙
- IndexedDB、Cache Storage、録音Blobを選択的または一括削除
- アプリ本体のキャッシュ削除と学習データ削除を混同しない
